In five minutes: what it flags, how I know the flags are right, and where it is still weak.

Most transactions are fine. Reading every row of an export to find the few odd ones is slow. fraudsense reads the CSV and hands back a short list, and every item on it says why it is there. Promise: by the end you will know what it flags, how I checked it myself, and where it is weak.

Two rules: an amount 5× the customer's average, or 5+ transactions in 10 minutes. Python standard library only.

This is output copied from a real run, not a live run. Score: 500 synthetic transactions in, 18 flagged, written to a CSV report. Click: explain one of them. T00101 is 7.2 times this customer's average and the seventh transaction in ten minutes. The point: you never get a score without the reason behind it.

3 / 5 · Why it works

I wrote the answer before the test

A planted test file:

15 ordinary buys,
$42.75 to $58.00
mean 50.4, counted by hand

T9001: $600.00
about 11.9× that

Written down on 11 Oct, before any test existed: T9001 is flagged, and scores above all 15.

Then I broke the rule on purpose, rules.py line 9:

AMOUNT_RATIO_THRESHOLD = 50.0
$ python -m unittest tests.test_planted
FAILED (failures=1)

$ git restore fraudsense_core/rules.py
$ python -m unittest tests.test_planted
OK

red when it's wrong,
green when it's right

The id T9001 and the expected result were mine, not the agent's.

How do I know the program does what I meant, and not just what the agent wrote? A planted file: one customer, fifteen normal purchases, average 50.4, counted by hand. The assistant proposed those values and I checked and accepted them. Then one purchase of 600, about twelve times that. The id T9001 and the expected result were mine, written down before a test existed. Then I broke the threshold, 5 to 50, and the test went red. Put it back, green. The whole suite is 82 tests, all passing.

Set the pass mark before you look

Keep the 5× rule if, on outside data, it catches ≥ 30% of fraud with precision ≥ 50%.
3 Oct
c1effb0
Sparkov (simulated), 26,658 transactions, 157 fraud:
recall 0.433 ✓   precision 0.136 ✗   68/157

My own rule failed my own bar.

Because the bar was in git first, I couldn't move it. So 5× is not validated, and my page says so.

One concrete moment from the repository. On 2 October I committed the question and the pass mark before measuring anything: at least 30 percent recall and at least 50 percent precision. The next day: it caught 68 of 157 frauds, recall fine, but only 68 of its 500 flags were fraud. Precision 0.136. Fail. Writing the bar down first meant I could not quietly lower it afterwards. So I publish the weak numbers instead.
